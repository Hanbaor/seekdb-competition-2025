## 4. 当前倒排索引的存储格式推断

### 4.1 基于代码的推断

**倒排索引表结构**（推断）：
```
inverted_index_table:
  token (VARCHAR)     - PRIMARY KEY, 分词
  doc_id (BIGINT)     - PRIMARY KEY, 文档ID
  doc_length (INT)    - 文档长度
  token_freq (INT)    - 词频（可能）
```

**查询时返回**：
- `inv_scan_domain_id_col_` → doc_id
- `inv_scan_doc_length_col_` → doc_length
- **没有** id, base_id, docid_col 等标量字段

### 4.2 当前的数据流

```
SQL: SELECT docid_col FROM items1 WHERE MATCH(...) AND id < 1000

执行流程：
1. ObDASTextRetrievalIter 扫描倒排索引
   返回：doc_id, doc_length
   
2. ObDASFuncDataIter 接收 doc_id
   add_doc_id() 过滤（硬编码 > 1000）
   
3. MAIN_LOOKUP_ITER 回表查询主表
   SELECT id, base_id, docid_col FROM items1 WHERE rowid = ...
   ↓ 10ms × N次
   
4. 应用过滤 (id < 1000, base_id IN (...))
   
5. 返回结果
```

## 8. 初步结论

### 8.1 当前架构特点
1. ✅ **文档ID明确**：使用 `ObDocIdExt` 存储，是 uint64 类型
2. ✅ **回表机制明确**：通过 `MAIN_LOOKUP_ITER` 实现，可以被屏蔽
3. ✅ **HashMap 可用**：FTS 模块已使用 `ObHashMap`，可复用
4. ❌ **索引扩展不明确**：还需要深入调查索引构建和存储格式

### 8.2 最可行的方案（初步）
**外部 HashMap 映射方案**：
```
索引构建时：
  扫描主表 → 构建倒排索引
         → 同时填充 HashMap: doc_id → {id, base_id, docid_col}

查询时：
  倒排索引扫描 → 获取 doc_id
  查询 HashMap → 获取标量字段
  应用过滤 → 屏蔽回表
```

**优点**：
- 不修改索引格式
- 实现相对简单
- 可以快速验证

**缺点**：
- 需要额外内存
- HashMap 需要持久化（或在查询前加载）

### 9.1 四个辅助表

**文件位置**：`src/rootserver/ddl_task/ob_fts_index_build_task.cpp:40-62`

全文索引实际上创建了**4个辅助表**：

```cpp

  uint64_t rowkey_doc_aux_table_id_;     // 1. FTS_ROWKEY_DOC表
  uint64_t doc_rowkey_aux_table_id_;     // 2. FTS_DOC_ROWKEY表
  uint64_t domain_index_aux_table_id_;   // 3. 倒排索引表（核心）
  uint64_t fts_doc_word_aux_table_id_;   // 4. FTS_DOC_WORD表
};
```

**表结构推断**：

```sql
-- 1. FTS_ROWKEY_DOC: rowkey → doc_id 映射
CREATE TABLE fts_rowkey_doc (
  rowkey      -- 主表的主键（或组合键）
  doc_id      -- 分配的文档ID
);

-- 2. FTS_DOC_ROWKEY: doc_id → rowkey 映射（反向）
CREATE TABLE fts_doc_rowkey (
  doc_id      -- 文档ID
  rowkey      -- 主表的主键
);

-- 3. DOMAIN_INDEX (倒排索引表): 核心
CREATE TABLE fts_index (
  token       VARCHAR   -- 分词
  doc_id      BIGINT    -- 文档ID
  doc_length  INT       -- 文档长度
  token_freq  INT       -- 词频（可能）
  -- ❌ 没有 id, base_id, docid_col
);

-- 4. FTS_DOC_WORD: 文档-词语关系
CREATE TABLE fts_doc_word (
  doc_id      -- 文档ID
  word        -- 词语
  word_count  -- 词语在文档中的次数
);
```

### 9.2 索引构建流程（推断）

```
用户执行：CREATE FULLTEXT INDEX idx ON items1(fulltext_col)

1. ObFtsIndexBuildTask 初始化
   ├─ 检查是否需要 doc_id (use_doc_id_)
   ├─ 创建4个辅助表
   └─ 启动构建任务

2. 扫描主表 items1
   FOR EACH row IN items1:
     ├─ 分配 doc_id (auto-increment或tablet_sequence)
     ├─ 插入 fts_rowkey_doc: (row.id, doc_id)
     ├─ 插入 fts_doc_rowkey: (doc_id, row.id)
     ├─ 分词 row.fulltext_col
     └─ FOR EACH token:
         ├─ 插入 fts_index: (token, doc_id, doc_length, freq)
         └─ 插入 fts_doc_word: (doc_id, token, count)

3. 构建完成
```

**关键发现**：
- ✅ **已有 doc_id 分配机制**
- ✅ **已有 rowkey ↔ doc_id 映射表**
- ❌ **倒排索引表不存储 id, base_id, docid_col**

## 10. 外部Map映射方案（完整设计）

### 10.1 方案概述

由于修改倒排索引表结构可能违反规则且复杂度高，采用**外部HashMap映射**方案：

**核心思想**：
- 在索引构建时，同步构建一个 `doc_id → 标量字段` 的映射
- 在查询时，使用这个映射替代回表

### 10.2 HashMap 数据结构

```cpp
// 标量字段结构体
struct ScalarFields {
  uint64_t id;              // 主表的 id 字段
  ObString base_id;         // 主表的 base_id 字段
  ObString docid_col;       // 主表的 docid_col 字段
  
  ScalarFields() : id(0), base_id(), docid_col() {}
  ScalarFields(uint64_t id_, const ObString &base_id_, const ObString &docid_col_)
    : id(id_), base_id(base_id_), docid_col(docid_col_) {}
};

// 全局HashMap（或作为某个类的成员）
class ObFtsScalarFieldsCache {
private:
  ObHashMap<uint64_t, ScalarFields> mapping_;  // doc_id → 标量字段
  ObArenaAllocator allocator_;                 // 用于存储字符串
  
public:
  int init(int64_t capacity);
  int add_mapping(uint64_t doc_id, uint64_t id, 
                  const ObString &base_id, const ObString &docid_col);
  int get_scalar_fields(uint64_t doc_id, ScalarFields &fields);
};
```

### 10.4 查询阶段：使用HashMap

**修改位置**：`src/sql/das/iter/ob_das_text_retrieval_iter.cpp`

```cpp
int ObDASTextRetrievalIter::inner_get_next_row()
{
  int ret = OB_SUCCESS;
  
  while (OB_SUCC(ret)) {
    // 1. 扫描倒排索引（现有逻辑）
    if (OB_FAIL(inverted_idx_scan_iter_->get_next_row())) {
      break;
    }
    
    // 2. 获取 doc_id
    uint64_t doc_id = get_doc_id();
    
    // ========== 3. 新增：查询 HashMap ==========
    ScalarFields fields;
    if (OB_FAIL(g_fts_scalar_cache.get_scalar_fields(doc_id, fields))) {
      LOG_WARN("failed to get scalar fields", K(doc_id));
      return ret;
    }
    
    // ========== 4. 新增：应用过滤 ==========
    if (fields.id >= 1000) {
      continue;  // 过滤掉
    }
    
    if (fields.base_id != "base_1" && fields.base_id != "base_2") {
      continue;  // 过滤掉
    }
    
    // ========== 5. 新增：设置输出字段 ==========
    ObEvalCtx *eval_ctx = ir_rtdef_->get_inv_idx_scan_rtdef()->eval_ctx_;
    
    // 设置 docid_col（替代回表获取）
    docid_col_expr->locate_datum_for_write(*eval_ctx)
        .set_string(fields.docid_col);
    docid_col_expr->set_evaluated_projected(*eval_ctx);
    
    // 设置 relevance（原有逻辑）
    float relevance = get_relevance();
    relevance_expr->locate_datum_for_write(*eval_ctx).set_float(relevance);
    
    // 6. 返回（只返回通过过滤的行）
    return OB_SUCCESS;
  }
  
  return ret;
}
```
