## 二、重新审视“新路径”可行性

你想要的是：

> 对于比赛这条 FTS 查询，全程只经历  
> `token → doc_id → (g_fts_scalar_cache) → 所有需要的标量列 → 谓词/排序 → 结果`  
> 不走任何真正的主表读。

基于当前代码，这**是可行的**，并且不需要完全新造一棵执行树，原因：

1. **倒排→doc_id 已有完整实现**（[ObTextRetrievalMerge](cci:1://file:///home/tian/seekdb/src/sql/das/ob_text_retrieval_op.cpp:94:0-110:1) / `ITER_TREE_TEXT_RETRIEVAL`）。
2. **doc_id→缓存→expr 的入口已经存在**（[ObDASCacheLookupIter::inner_get_next_rows](cci:1://file:///home/tian/seekdb/src/sql/das/iter/ob_das_functional_lookup_iter.cpp:185:0-211:1)）。
3. 我们只需要让：
   - FTS 计划**生成时**把“哪一个 expr 对应 id/base_id/docid_col”等信息下传；
   - Cache Lookup **命中时**按这些列标识精确填充；
   - 正常路径下**不再调用真正的 do_index_lookup 回表**。

相当于把 [ObDASCacheLookupIter](cci:2://file:///home/tian/seekdb/src/sql/das/iter/ob_das_cache_lookup_iter.h:48:0-115:1) 强化成一个“FTS Scalar Fetch 终端算子”，而不是“Local Lookup + Cache” 混合体。

### 阶段 2：在 CTDef / Expr 上打列标识

**目标**：让 [ObDASCacheLookupIter](cci:2://file:///home/tian/seekdb/src/sql/das/iter/ob_das_cache_lookup_iter.h:48:0-115:1) 在 `OUTPUT_ROWS` 阶段知道：

- 哪一列是：`id`、`base_id`、`docid_col`、`_score`（BM25）……

#### 2.1 设计一个轻量标识结构

建议只为比赛 FTS 路径添加一个简单的 enum/tag，例如：

```cpp
enum ObFtsScalarKind {
  FTS_SCALAR_NONE = 0,
  FTS_SCALAR_ID,
  FTS_SCALAR_BASE_ID,
  FTS_SCALAR_DOCID_COL,
  // 将来可扩：FTS_SCALAR_OTHER_xxx
};
```

挂载方式有两种：

- **方式 A（快速 hack，比赛足够）**  
  在 [ObExpr](cci:2://file:///home/tian/seekdb/src/sql/engine/expr/ob_expr.h:444:0-970:1) 里找一个可用的扩展位（比如 `extra_info_` 派生结构），加一个字段 `fts_scalar_kind_`。  
  在 ObExpr 生成阶段（codegen）为特定列设置这个 tag。

- **方式 B（更干净）**  
  在负责这条 FTS DAS 的 CTDef 里增加：

  ```cpp
  struct FtsScalarSlot {
    int64_t result_output_idx;   // 在 result_output_ 里的位置
    ObFtsScalarKind kind;
  };
  ObArray<FtsScalarSlot> fts_scalar_slots_;
  ```

  然后在 [ObDASCacheLookupIter](cci:2://file:///home/tian/seekdb/src/sql/das/iter/ob_das_cache_lookup_iter.h:48:0-115:1) 里通过 `lookup_ctdef_->fts_scalar_slots_` 做映射。

就改动量和比赛周期看，**A 方案更容易落地**。

#### 2.2 在 FTS CG 阶段填这个标识

- 文件：[observer/table/fts/ob_table_fts_cg_service.cpp](cci:7://file:///home/tian/seekdb/src/observer/table/fts/ob_table_fts_cg_service.cpp:0:0-0:0)
- 在 [generate_text_retrieval_dep_exprs()](cci:1://file:///home/tian/seekdb/src/observer/table/fts/ob_table_fts_cg_service.cpp:70:0-216:1) 中，你已经能拿到：
  - data table 的 schema；
  - 各列的 column_id / 列名（通过 `get_column_schema` 和 `get_column_name_str`）。
- 对于比赛的固定 schema（`items1(id, base_id, docid_col, fulltext_col, ...)`），可以在这里根据列名/column_id，记住：
  - 哪个 RawExpr 对应 `id`；
  - 哪个 RawExpr 对应 `base_id`；
  - 哪个 RawExpr 对应 `docid_col`；
- 在 Static Engine CG 把 RawExpr 降为 ObExpr 时，把这个“列类别”写进 ObExpr 的 `fts_scalar_kind_`。

### 阶段 3：改造 [ObDASCacheLookupIter](cci:2://file:///home/tian/seekdb/src/sql/das/iter/ob_das_cache_lookup_iter.h:48:0-115:1) 的 `OUTPUT_ROWS` 阶段

**目标**：命中缓存时，**只用缓存完成标量补齐**，并且按列标识精确写入。

文件：[sql/das/iter/ob_das_cache_lookup_iter.cpp](cci:7://file:///home/tian/seekdb/src/sql/das/iter/ob_das_cache_lookup_iter.cpp:0:0-0:0)  
函数：[int ObDASCacheLookupIter::inner_get_next_rows(int64_t &count, int64_t capacity)](cci:1://file:///home/tian/seekdb/src/sql/das/iter/ob_das_functional_lookup_iter.cpp:185:0-211:1)

你当前改造的大致结构：

- `INDEX_SCAN`：从 index_table_iter 获取行，调用 [add_rowkeys](cci:1://file:///home/tian/seekdb/src/sql/das/iter/ob_das_functional_lookup_iter.cpp:223:0-233:1) 收集 rowkey，保存 doc_id 到 `cached_doc_ids_`。
- `DO_LOOKUP`：调用 [do_index_lookup()](cci:1://file:///home/tian/seekdb/src/sql/das/iter/ob_das_functional_lookup_iter.cpp:235:0-316:1)（旧逻辑）。
- `OUTPUT_ROWS`：
  - 遍历 `cached_doc_ids_`：
    - [get_scalar_fields(doc_id, fields)](cci:1://file:///home/tian/seekdb/src/sql/das/ob_fts_scalar_cache.cpp:99:0-115:1)
    - 遍历 `lookup_ctdef->result_output_` 按 type/slot heuristic 回填。

**下一步需要做的事情**：

1. **用列标识替代 heuristic：**

   ```cpp
   for each ObExpr *expr in lookup_ctdef->result_output_ {
     switch (expr->fts_scalar_kind_) {
       case FTS_SCALAR_ID:
         // 数值
         datum.set_uint(fields.id_);
         break;
       case FTS_SCALAR_BASE_ID:
         // 申请字符串内存，拷贝 fields.base_id_
         break;
       case FTS_SCALAR_DOCID_COL:
         // 拷贝 fields.docid_col_
         break;
       default:
         // 非 scalar 缓存列：保持原有逻辑（例如 score 表达式、其他下推列等）
         break;
     }
   }
   ```

   这样就**彻底摆脱了 string_slot 猜测**，和“原路径回表填 expr 的语义”对齐。

2. **正常路径下不再回表：**

   - 对于 cache 命中场景（你假设 100% 命中）：
     - `OUTPUT_ROWS` 完成后，可以直接认为该 iter 已经产出所有需要的行。
     - 可以把 `state_` 直接改为 `FINISHED`（或者保持当前 state 机，但不再切回 `INDEX_SCAN/DO_LOOKUP`）。
   - 对于 cache miss（理论上不该发生）：
     - 可以简单记录一条 `LOG_ERROR("fts scalar cache miss", K(doc_id))`，然后：
       - 要么直接 `continue` 跳过该 doc_id；
       - 要么 fallback：调用原来的 [check_index_lookup](cci:1://file:///home/tian/seekdb/src/sql/das/iter/ob_das_functional_lookup_iter.cpp:318:0-334:1) + `DO_LOOKUP` 路径兜底。
     - 比赛场景下，你完全可以**不实现 fallback**，只做 `continue`，以减少复杂度。

3. **保留 `index_proj_rows_` 逻辑**（如你现在代码中那样），保证如果 plan 里有 index 投影需求，依然能从 index 侧 expr 填回。
