# RAG系统改进总结

## 🔄 改进历程

### 版本1：基础实现 ❌
- **问题**：文件名匹配率 0%
- **原因1**：spaCy NER在中文短查询上失效（实体提取0%）
- **原因2**：源归因固定取第一个文档
- **得分**：~44分

### 版本2：jieba NER + 简单得分排序 ⚠️
- **改进**：
  - 用jieba替代spaCy进行查询实体提取
  - 按检索得分（chunk数量）排序选择源文档
- **效果**：
  - Local Search: 1次 → 13次 ✅
  - 实体提取成功率: 0% → 78.6% ✅
  - 但文件名匹配率仍然 0% ❌
- **新问题**：所有文档返回相同数量的chunks（6个），得分完全相同，排序无效

### 版本3：模糊匹配实体 🔍
- **改进**：
  - 将jieba提取的关键词模糊匹配到Graph中的实体
  - 例如："千味央厨" → "千味央厨公司"
- **效果**：
  - 实体匹配成功率提升
  - Local Search次数增加
- **新问题**：
  - 正确文档的Graph质量差（没有"千味央厨"相关实体）
  - 导致返回chunk数少
  - 得分低 → 排名靠后

### 版本4：LLM Re-ranking ⭐ (当前)
- **核心思路**：让LLM从所有检索结果中选择最相关的文档

#### 工作流程
```
1. 检索所有20个文档
   ↓
2. 每个文档截断到1000字符
   ↓
3. 拼接成候选列表给LLM
   ↓
4. LLM返回最相关文档的编号（1次调用）
   ↓
5. 更新得分：选中文档=1.0，其他递减
   ↓
6. 使用选中文档生成答案（1次调用）
   ↓
7. 使用选中文档作为源归因
```

#### 优势
1. **每问题仅2次LLM调用**：
   - 1次选择文档（reranking）
   - 1次生成答案
   - 总共：14问题 × 2 = 28次

2. **语义理解准确**：
   - LLM能理解文档与问题的真实相关性
   - 不受Graph质量影响
   - 不受chunk数量影响

3. **降级策略**：
   - 如果LLM选择失败，降级到基于文本长度的简单评分

## 🔧 关键代码

### LLM选择prompt
```python
selection_prompt = f"""你是一个文档相关性评估专家。

问题：{question}

候选文档：
[文档1] 文档名...
内容片段...

[文档2] 文档名...
内容片段...

请返回最相关的文档编号（1-15）。
只返回数字，不要解释。"""
```

### 得分更新
```python
selected_idx = int(llm_response.strip()) - 1

for idx, res in enumerate(scored_results):
    if idx == selected_idx:
        res["score"] = 1.0  # 最相关
    else:
        # 其他文档按距离递减
        res["score"] = max(0.1, 1.0 - abs(idx - selected_idx) * 0.1)
```

## 📝 注意事项

1. **LLM调用成本**：
   - 每个问题2次调用
   - 需要控制prompt长度（当前1000字符/文档）

2. **容错机制**：
   - LLM返回格式不对 → 降级到简单评分
   - LLM选择索引越界 → 降级到简单评分

3. **API限制**：
   - 使用async并发，受max_concurrent控制
   - 当前设置14（全部并行）
